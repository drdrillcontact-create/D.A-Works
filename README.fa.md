# DA Works — دسکتاپ و Android

DA Works فضای شخصی برای ثبت ایده‌ها، پروژه‌های موسیقی، پرامپت‌ها، متن ترانه و کارهای روزانه است. یک رابط React مشترک در دو نسخه عرضه می‌شود: **نصاب Windows (Electron)** و **اپلیکیشن Android (Capacitor)** — و این دو با هم سینک می‌شوند.

## تازه‌های نسخهٔ ۱٫۱

- **گزینهٔ سینک در نسخهٔ دسکتاپ**: در بخش `Sync` یک کلید اصلی «همگام‌سازی با اپلیکیشن Android» اضافه شده، به‌علاوهٔ کلیدهای «سینک خودکار»، «سینک بعد از هر ذخیره» و انتخاب فاصلهٔ بررسی خودکار.
- **طراحی مخصوص موبایل**: در Android دیگر خبری از سایدبار دسکتاپ نیست؛ نوار بالای برنامه، نوار پایین (Home / Sections / Write / Sync)، لیست تمام‌صفحهٔ بخش‌ها، دکمه‌های اندازهٔ انگشت و فونت خوانا جای آن را گرفته‌اند. متن فارسی و انگلیسی هم با `dir="auto"` درست چیده می‌شود.
- **نوشتن آفلاین**: هر ورودی اول روی همان دستگاه ذخیره می‌شود. اگر اینترنت نباشد، وضعیت «آفلاین» و نشان «تغییرهای سینک‌نشده» نمایش داده می‌شود و به‌محض اتصال، ارسال انجام می‌شود.
- **دریافت خودکار در دسکتاپ**: نسخهٔ ویندوز فایل مشترک را روی دیسک watch می‌کند، هنگام بیدارشدن سیستم از sleep و آنلاین‌شدن دوباره بررسی می‌کند و تغییرهای موبایل را بدون دخالت کاربر می‌گیرد.
- **نمای دستگاه‌ها و گزارش سینک**: می‌بینی هر دستگاه آخرین بار کِی سینک کرده و آخرین تلاش‌ها موفق بوده‌اند یا نه.
- **آیکون و اسپلش اختصاصی**: آیکون لانچر، اسپلش‌اسکرین اندروید و آیکون فایل `exe` همه با برند DA Works جایگزین شدند.

## امکانات

- بخش‌های Prompts، Music، Video، Plugins، Suno Prompts، Lyrics، Tasks و Quick Notes
- جست‌وجو، آرشیو، بازیابی، حذف و ذخیرهٔ محلی
- پنج زبان در بخش Lyrics: فارسی، انگلیسی، ترکی آذربایجانی، ترکی استانبولی و روسی
- همگام‌سازی بین Android و Windows با یک فایل مشترک Google Drive
- نگه‌داشتن هر دو نسخه در صورت تعارض و جلوگیری از بازگشت ورودی‌های حذف‌شده

## راه‌اندازی همگام‌سازی (یک‌بار)

این روش از file picker خود Android و پوشهٔ محلی Google Drive for desktop در Windows استفاده می‌کند؛ نیازی به ساخت Google OAuth client یا دادن رمز حساب به برنامه نیست.

1. **روی یکی از دستگاه‌ها فایل را بساز.** در بخش `Sync` دکمهٔ «ساخت فایل جدید» را بزن و `DA Works Sync.json` را داخل Google Drive ذخیره کن.
2. **روی دستگاه دیگر همان فایل را انتخاب کن.** دکمهٔ «انتخاب فایل موجود» → همان فایل را از Google Drive انتخاب کن.
3. **در Windows**: برنامهٔ **Google Drive for desktop** را نصب کن، فایل ساخته‌شده را داخل پوشهٔ Drive ببین و از داخل DA Works همان مسیر را انتخاب کن. بهتر است روی فایل راست‌کلیک کنی و **Available offline** را بزنی.
4. **کلید «همگام‌سازی» را در هر دو دستگاه روشن کن.** تمام.

### جریان روزمره‌ای که خواستی

> وقتی به دسکتاپ دسترسی نداری، در اپ اندروید می‌نویسی و «همگام‌سازی اکنون» را می‌زنی؛ بعد که کامپیوتر آنلاین شد، خودش همان نوشته‌ها را می‌گیرد.

- روی گوشی می‌نویسی → ورودی فوراً روی گوشی ذخیره می‌شود (حتی آفلاین).
- «همگام‌سازی اکنون» را می‌زنی (یا اگر «سینک خودکار» روشن باشد، خودش با آنلاین‌شدن می‌فرستد) → فایل داخل Google Drive به‌روز می‌شود.
- کامپیوتر که روشن/آنلاین می‌شود، Google Drive فایل را پایین می‌آورد؛ DA Works ویندوز همان لحظه فایل را می‌خواند، با داده‌های محلی ادغام می‌کند و نتیجه را ذخیره می‌کند.
- اگر ویندوز هم چیزی نوشته باشد، در همان سینک به گوشی برمی‌گردد.

نکته: نسخهٔ ویندوز باید **در حال اجرا** باشد (باز یا minimize) تا سینک خودکار انجام شود. اگر بسته باشد، دفعهٔ بعد که بازش کنی همه‌چیز را یک‌جا می‌گیرد. میان‌بر `Ctrl+Shift+S` هم هر لحظه سینک دستی را اجرا می‌کند.

## ساخت Windows x64

Node.js نسخهٔ `22.12` یا جدیدتر:

```powershell
npm ci
npm test
npm run dist:win
```

خروجی در پوشهٔ `release` با نامی شبیه `DA-Works-Setup-1.1.0-x64.exe` قرار می‌گیرد. در GitHub Actions نیز workflow **Build Windows x64 installer** همین نصاب را می‌سازد (Artifact: `DA-Works-Windows-x64`).

## ساخت Android APK

برای ساخت محلی به Node.js نسخهٔ `22.12` یا جدیدتر، JDK `21` و Android SDK نیاز است:

```bash
npm ci
npm test
npm run android:apk
```

APK آزمایشی (debug-signed) در این مسیر ساخته می‌شود:

```text
android/app/build/outputs/apk/debug/app-debug.apk
```

یا در GitHub Actions، workflow **Build Android APK** را اجرا و Artifact به نام `DA-Works-Android-APK` را دانلود کن. این APK برای نصب مستقیم/آزمایش است؛ برای انتشار در Google Play و به‌روزرسانی پایدار باید keystore انتشار اختصاصی تنظیم شود.

## توسعه

```bash
npm ci
npm run electron:dev     # نسخهٔ دسکتاپ با hot reload
npm run dev              # فقط رابط وب در مرورگر
npm run android:sync     # کپی خروجی وب داخل پروژهٔ Android
npm test                 # تست منطق workspace و sync
```

برای دیدن رابط در یک preview یا تونل:

```bash
VITE_HOST=0.0.0.0 VITE_ALLOWED_HOSTS=.example.com VITE_HMR_CLIENT_PORT=443 npm run dev
```

در مرورگرِ Chromium که File System Access API دارد، بخش Sync کار می‌کند و می‌توانی همان فایل مشترک را انتخاب کنی؛ در مرورگرهای دیگر یا داخل iframe، به‌جای آن پیام راهنما نشان داده می‌شود.

آیکون‌ها و اسپلش‌ها از روی کد تولید می‌شوند:

```bash
python3 -m pip install pillow
python3 scripts/generate-brand-assets.py
```

## نکات داده و حریم خصوصی

- داده‌های اصلی برنامه روی همان دستگاه می‌مانند؛ سینک فقط وقتی انجام می‌شود که هم فایل مشترک انتخاب شده باشد و هم کلید همگام‌سازی روشن باشد.
- تنظیمات سینک (روشن/خاموش، فاصلهٔ بررسی) مخصوص هر دستگاه است و وارد فایل مشترک نمی‌شود.
- اگر یک ورودی روی دو دستگاه متفاوت تغییر کند، نسخهٔ بازنده به‌صورت یک کپی جدا با برچسب `(conflict copy)` نگه داشته می‌شود؛ چیزی از دست نمی‌رود.
- حذف‌ها با tombstone ثبت می‌شوند تا یک دستگاه قدیمی، ورودی حذف‌شده را برنگرداند.
- فایل Drive شامل متن‌های workspace به‌صورت JSON معمولی است و رمزگذاری سرتاسری ندارد؛ دسترسی فایل را با حساب Google خودت کنترل کن.
- برای انتشار عمومی، نسخهٔ Windows را code-sign و APK را با keystore انتشار امضا کن.
